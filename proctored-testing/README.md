# AeroSoc BIT Mesra Proctored Testing Platform

**Author / Credits:** Anurag Kumar Verma

## 1. Purpose

The platform is built specifically for AeroSoc BIT Mesra's Recruitment Online Assessment (OA). It addresses the need for a scalable, privacy-first testing environment that prevents cheating without using intrusive, instant-lockout mechanics. By employing an "observe and log" duration-based model, it ensures a seamless experience for candidates and zero media storage, while giving administrators concrete data on academic integrity.

## 2. Architecture Overview

**Core Framework:** Next.js 16.

**Authentication and State:** Firebase (Google Auth with strict .env admin constraints, RTDB for telemetry, Firestore for exam data).

**Edge Proctoring Engine:** MediaPipe (FaceMesh for face presence, Vision Tasks for cell phone detection). All processing executes strictly on the client-side browser to guarantee zero audio/video storage.

**Data Flow:** Local "stopwatch" logging computes the exact duration of an infraction (e.g., out of fullscreen, phone detected) and sends a single debounced write to Firebase RTDB upon completion.

**AI Analytics:** Groq API ingests the duration-based RTDB logs to generate a final, human-readable proctoring summary for the administrative dashboard.

**High-Concurrency Resilience:** The platform is engineered to handle "Thundering Herd" scenarios through edge caching, which neutralizes database read spikes during simultaneous mass starts. A custom local storage integration guarantees perfect offline resilience, protecting student progress against network instability. A secure serverless relay handles bulk submissions with isolated writes to eliminate database contention.

## 3. Security and Integrity Mechanisms

The system enforces a strict client-side security perimeter to ensure academic integrity. The local machine learning pipeline verifies that a face is present, the camera is uncovered, and the microphone is picking up ambient audio before granting access. Once inside the examination interface, rigorous DOM restrictions disable text selection, drag-to-copy, and context menus. Keydown listeners block keyboard shortcuts for copying or printing, and CSS print media queries obscure all content to defeat print-to-PDF screenshot attacks. The Page Visibility API monitors for tab switching or browser minimization, logging infractions immediately.

## 4. Deployment and Usage

**Deployed Application:** https://proctored-testing.vercel.app

**Candidate Workflow:** Candidates authenticate exclusively via pre-approved Google accounts. After granting hardware permissions and passing the local environmental checks, the interface enforces a fullscreen constraint and delivers the examination. Answers are cached locally in real-time to survive network drops. Upon completion or timer expiration, the answers are securely relayed to the server.

**Administrator Workflow:** Authorized administrators access a secure dashboard to monitor active test takers, review telemetry data, and analyze human-readable proctoring reports generated by the Groq AI integration. This allows for informed, evidence-based decisions regarding candidate integrity.
